# Story B-3: Receipt upload UI
Status: Review (QA: see docs/qa/B-gate.md)

**Story:** As a shopper, I want to photograph or upload my receipt in one tap, so that the audit starts immediately.

## Acceptance Criteria
1. AC1 `/receipt` shows a large "Upload or photograph your receipt" button wrapping `<input type="file" accept="image/*" capture="environment">`.
2. AC2 A preview thumbnail of the chosen image is shown.
3. AC3 The image is resized to max 1500 px via `fileOrCanvasToJpegBase64` (HEIC handled) before upload.
4. AC4 While reading: "Reading your receipt…" with a spinner; button disabled.
5. AC5 On error: "Try a flatter, brighter photo" with a retry button; no crash.
6. AC6 On success the items are handed to the ItemsTable (B-4).
7. AC7 Layout works at 390 px width; tap targets ≥ 44 px.

## Tasks
- [ ] T1 Overwrite `app/receipt/page.tsx` as a client component with state machine `idle | reading | review | checking | done | error` (AC1–6)
- [ ] T2 Call `fileOrCanvasToJpegBase64(file, 1500)` (verify signature in lib/image.ts) then POST `/api/receipt` (AC3)
- [ ] T3 Responsive styling with Tailwind (whatever A set up), pink theme per CLAUDE.md UI rules (AC7)
- [ ] T4 `npm run build`

## Dev Notes
- Files: `app/receipt/page.tsx`, small helpers in `components/receipt/`.
- Revoke object URLs on unmount. Do not persist the image anywhere.
- Page reads `?sample=1` to later show the banner (B-4).

## Testing
Manual: upload a JPEG, a HEIC, a non-image; throttle network; check 390 px in devtools.
