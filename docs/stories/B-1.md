# Story B-1: Receipt totals library + tests
Status: Review (QA: see docs/qa/B-gate.md)

**Story:** As a shopper, I want the Pink Tax maths to be exact and predictable, so that the number in my summary can be trusted.

## Acceptance Criteria
1. AC1 `itemsSum(items)` sums `line_total` of ticked/readable items; null/unreadable lines count 0; result rounded to 2 dp.
2. AC2 `hasMismatch(items, receipt_total, tolerance=0.05)` is true when `|itemsSum − receipt_total| > tolerance`; false when receipt_total is null/undefined.
3. AC3 `pinkTaxForItem(comparison, qty)` = `(u_target − u_best) × target.quantity × qty` only if `gap > 0` and both unit prices known (price_gbp / quantity); otherwise 0.
4. AC4 `summarise(results, tripsPerYear)` returns `{pinkTaxPaid, couldHaveSaved, yearlyEstimate, itemsChecked, itemsWithGap}`; yearly = pinkTaxPaid × tripsPerYear.
5. AC5 No scores are computed or re-derived; unit prices are read from the Comparison's products only.
6. AC6 Tests cover: one gap, reverse gap (0), missing data (0), mismatch true/false, yearly maths.

## Tasks
- [ ] T1 Create `lib/receipt/totals.ts` with the four pure functions (AC1–5)
- [ ] T2 Create `lib/receipt/totals.test.ts` (AC6) — use the project's test runner if A set one up; otherwise `node:test` via `npx tsx --test` (no new deps)
- [ ] T3 `npm run build` passes (all ACs)
