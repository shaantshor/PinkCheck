# Story B-4: Editable items table
Status: Draft

**Story:** As a shopper, I want to review and fix what was read from my receipt, so that the audit uses the right items and prices.

## Acceptance Criteria
1. AC1 Table columns: ✓ / name / qty / price; name and price editable (qty editable if time allows).
2. AC2 Female-targeted personal-care items are pre-ticked; others unticked.
3. AC3 Unreadable lines are visually highlighted, show `raw_text`, and prompt the user to fill in a price/name; they cannot be ticked until a price is entered.
4. AC4 When `hasMismatch(items, receipt_total)` the banner "Some items may be misread, please check" shows; it disappears when edits resolve the mismatch.
5. AC5 When the URL has `?sample=1`, a "Sample receipt" banner is shown.
6. AC6 Max 5 items can be ticked; the 6th tick is blocked with a short hint.
7. AC7 Displays store name and receipt total as read; prices labelled "from your receipt".

## Tasks
- [ ] T1 `components/receipt/ItemsTable.tsx` with props `{items, receiptTotal, onChange, ticked, onTick}` (AC1–3, 6, 7)
- [ ] T2 Mismatch banner using `hasMismatch` from `lib/receipt/totals` (AC4)
- [ ] T3 Sample banner via `useSearchParams` (wrap in Suspense for build) (AC5)
- [ ] T4 Wire into `app/receipt/page.tsx` review state (AC1)
- [ ] T5 `npm run build`; **QA gate 1** after this story

## Dev Notes
- Pre-tick rule: `gender_target === 'female'` and not unreadable. Personal-care filtering is by name keywords only as a tie-breaker; don't over-engineer.
- Editing a price recomputes mismatch live. Parse with `parseFloat`, reject negatives.
- Keep `raw_text` immutable and always visible (small grey text).

## Testing
Manual: edit a price to trigger the banner; open `/receipt?sample=1`; tick 6 items; 390 px layout.
